# NAS 本地资料检索

本改造把下载的公开资料迁到 NAS，用“结构化同盘匹配 + 关键词段落排序”给 Codex 提供上下文。没有训练模型或调用嵌入 API，也不等同于上游现行商用断语库。

## 数据与范围

- `knowledge/original/`（容器内 `/knowledge/original/`）：既有 NAS 保留电脑 `data/ziwei-datasets/` 的原始文件、压缩分片、发布清单与许可证，约 17.96 GB；不执行包内旧脚本。这些运行资产被 Git 忽略，克隆不会自动取得。
- `resources/`：仓库古籍整理 JSON、对应 TS 原稿、《天纪》1848 条引文及讲次文件。部分古籍是精选，不能称全本。
- `index/knowledge.sqlite`：可再生的只读检索索引，不含用户档案或历史。按版本与日期保存独立 zstd 压缩块，每块最多 24 种时辰/性别组合，不展开约 89.7 GB JSONL。
- v3 原始 518400 条，过滤 2520 条不存在日期后索引 515880 条；v4 索引 674976 条，共 1190856 条有效样本，13 个主题。

## 解读过程

1. 服务端根据出生信息重新计算当前命盘，忽略客户端伪造的星曜和资料。
2. 按最新提问识别 13 维主题；简短追问可沿用上一条用户问题的主题。
3. 使用当前命盘的排盘日、时辰序号（0=子，11=亥）及性别查询 v4/v3。同日历输入不代表新旧引擎规则完全相同。无覆盖时明确说明，不用其他生日替代。
4. 根据主题宫位、主星、问题中提到的星曜，对古籍整理和有出处的引文进行关键词排序。只注入有限节选；原始全库不上传。
5. 将节选、出处编号与规则差异提示通过 stdin 交给 NAS 容器内 Codex CLI，保持原有流式输出。当前引擎的宫位、亮度、四化、年龄和大限优先于旧样本。
6. 服务端在成功解读末尾追加“本次检索资料”，列出实际提供的资料，不暗示每条都被 AI 采用。正文采用的观点要求用 `[资料N]` 标注。

引用链接打开 `/sources?ref=...`，登录后可查看对应原始主题全文或引文，包含版本、时辰、性别、主题、讲次/时间码与许可证。出处文本随解读一起保存在账号历史及 JSON 备份中；旧解读不自动重算，重新解读或追问会使用新资料。

单盘与合盘均支持检索；合盘资料标注甲/乙方并使用不重复的引用编号。合盘结果及追问、资料引用现在也保存到账号历史，JSON备份：v1为旧单盘，v2包含合盘，v3包含独立主题，v4启用专业/通俗双模式；四版均可导入，当前格式见[主题与模式说明](./AI主题标签.md)。

## 授权模式

默认 `KNOWLEDGE_USE_MODE=personal`，用于本人的非商业学习：数据集署名王多鱼AI / Renhuai123/ziwei-doushu，CC BY 4.0；《天纪》原话及数据集中混入的引文单独适用 CC BY-NC-SA 4.0，明确排除在数据集 CC BY 授权外。引用展示保留来源和非商业标记。

`commercial` 模式采取保守过滤：排除全部《天纪》及混合授权 v3/v4 正文，只检索古籍整理。可在受保护的 `runtime.env` 设置 `KNOWLEDGE_USE_MODE=commercial` 后重建容器配置；无需重新构建镜像。未制作可商用清洗数据集；保留原包不代表其中所有来源都获商用许可。v3 中的待授权来源目录、metadata-only 文件和联系草稿不参与检索。

## 配置与维护

```dotenv
KNOWLEDGE_DB_PATH=/knowledge/index/knowledge.sqlite
KNOWLEDGE_REQUIRED=true
KNOWLEDGE_USE_MODE=personal
```

Compose 将 `./knowledge:/knowledge:ro` 挂载给应用。索引不进 Docker 镜像、Git 或账号数据库。CLI 不获得检索工具或 Shell 权限；检索由服务端执行。必须检索时若索引缺失、损坏或未就绪，返回明确的 503，不默默假装检索成功。

`GET /api/knowledge`（需登录）返回索引状态和计数；`?ref=<稳定资料ID>` 仅返回索引中允许的条目，不能读取任意 NAS 文件。公开健康检查只返回 ready/disabled 与授权模式，不暴露目录或用户资料。

离线重建使用 Node.js 24（构建容器无需联网，约 1 GB 内存限制）：

```sh
node scripts/build-knowledge.mjs /knowledge /knowledge/index/knowledge-next.sqlite
```

重建需要 `original/` 与 `resources/` 布局。先写 `.building`，按源分片事务保存进度，检查 797 个分片、有效/无效计数与 SQLite 完整性后原子发布；中断可用同一路径继续。现存输出不会被覆盖。新文件校验后再切换配置，不删除当前索引。

更新前备份 Compose、运行配置、当前镜像和账号 SQLite 一致性快照。原始资料按 SHA-256 清单验证；索引可重建，不必每次复制整个资料库。回滚旧应用时保留 `data/`、`codex/` 和 `knowledge/`。
